# ROM Identification

Generated by `tools/rom/identify_rom.py`. This document contains only header
fields and checksums needed to identify *which* game/revision a dump is — it
does not contain, and must never contain, ROM byte dumps, code, graphics, or
text extracted from the ROMs themselves.

Both ROMs referenced here are user-supplied and live outside this repository
(in the sibling `roms/` workspace folder, which is not committed to git).

### Identity

The header title `MYSTIC QUEST` plus the Overseas destination code
identifies this as the **European PAL release of *Final Fantasy Adventure***
— published by Square in 1991 for the original Game Boy. The same game was
released as:

- Japan: *Seiken Densetsu: Final Fantasy Gaiden* (聖剣伝説 -Final Fantasy外伝-)
- North America: *Final Fantasy Adventure*
- Europe: **Mystic Quest** (this ROM) — not to be confused with the later,
  unrelated SNES title *Final Fantasy: Mystic Quest* (1993)

It is the first entry in what later became the *Mana* series. See
[docs/references.md](references.md) for external sources on this
identification, and cross-check notes on how the EU build may differ from
the more commonly documented US build.

**In-game language: German.** The cartridge/header title `MYSTIC QUEST`
is the English-language EU *brand name* Nintendo/Square used for this
release, but this specific dump's actual in-game dialogue text is German
(confirmed by the project owner; consistent with the font tile region
holding a German umlaut set `ÄÖÜäöüß` immediately adjacent to the main
charset — see
[reverse-engineering/rom-map.md](reverse-engineering/rom-map.md)'s font
entry). Don't assume English in-game text when reverse engineering
dialogue — see
[reverse-engineering/text.md](reverse-engineering/text.md) for how this
already changed the text-encoding search. Whether other-language text
(English, French — the font region has hinted at other accented sets,
still UNKNOWN) also exists in this ROM behind a language-select flag is
unconfirmed.

This ROM revision (EU/`MYSTIC QUEST`, SHA-1
`7cb65cb314e3f26b92549ddc7f4fc275186c6170`) is the only revision currently
verified against the workspace. All ROM-specific offsets recorded in
`docs/reverse-engineering/rom-map.md` are scoped to this exact hash unless
stated otherwise, per the project's [ROM profile](../src/import/rom_profiles.lua)
design (multiple revisions can be added later without this one changing).

### Bank layout implied by the header

MBC2, 256 KiB ROM = 16 banks of 16 KiB (`$0000-$3FFF` fixed bank 0,
`$4000-$7FFF` switchable banks 1-15). MBC2 provides no external cartridge
RAM chip; save data lives in the mapper's built-in 512×4-bit (256-byte)
RAM at `$A000-$A1FF`, with only the low nibble of each byte significant.
This constrains save-data reverse engineering: whatever persistent state
Mystic Quest keeps must fit in that 256-byte window.

## Tooling

`tools/rom/identify_rom.py <path> [<path> ...]` — stdlib-only, read-only,
prints a JSON report per file. Re-run it any time to re-verify a ROM; it
never writes anything and never embeds ROM content beyond the header/hash
fields shown above.
